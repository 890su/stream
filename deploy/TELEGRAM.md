# Telegram BY и PL — подключение аккаунтов

Шлюз на каждый аккаунт пишет переписку в ленту и отправляет ответы из ленты (`CONCEPT.md` §8.2,
`docs/plans/2026-11-17-p11-telegram.md`). Код — `gateway/telegram/` (Python, Telethon). Контейнеры `tg-by` и
`tg-pl` ставит `deploy/install.sh` вместе со Stream; пока вход не выполнен, на экране «Система» они
«нужен вход».

## 1. api_id и api_hash (один раз, на оба аккаунта)

1. Открыть https://my.telegram.org → войти своим номером → «API development tools».
2. Создать приложение: название `Stream`, платформа `Other`. Получить `api_id` (число) и `api_hash`.
3. На сервере дописать их в `/srv/stream/.env`:

```bash
sudo nano /srv/stream/.env
```

```
TG_API_ID=1234567
TG_API_HASH=0123456789abcdef0123456789abcdef
```

4. Перезапустить шлюзы, чтобы они увидели ключи:

```bash
cd /srv/stream/app/deploy && sudo docker compose up -d tg-by tg-pl
```

## 2. Вход в аккаунт (по разу на BY и PL)

```bash
cd /srv/stream/app/deploy && sudo docker compose run --rm -it tg-by login
```

Ввести номер телефона аккаунта, код, который пришёл в Telegram, и пароль двухэтапной проверки (если есть).
Вводит только владелец; ничего из этого не сохраняется, кроме сессии в `/srv/stream/tg/by/` (права 700).
То же для польского аккаунта — `tg-pl`.

В Telegram в «Настройки → Устройства» появится «Stream gateway». Завершить этот сеанс — значит отключить
шлюз; в ленте появится «Telegram BY: нужен вход».

Шлюз подхватывает сессию в течение 5 минут; сразу — `sudo docker compose restart tg-by`.

## 3. Что попадает в ленту

- Личные чаты с людьми — все. Лишний чат: открыть его в ленте (касание заголовка «Telegram BY · имя») →
  «Не отслеживать». Вернуть — ⋮ → «Система: источники и отправки» → «Не отслеживаются» → «Вернуть».
- Группы — только из папки **Stream** этого аккаунта: в Telegram создать папку «Stream» и добавить в неё
  рабочие группы. Убрали группу из папки — шлюз перестаёт её писать (в течение 10 минут).
- Каналы, боты, «Избранное» и служебный чат Telegram с кодами — никогда.
- Чат, который только начали отслеживать, подтягивается **за сегодня**; после простоя шлюз догоняет пропущенное.
- Голосовые, фото, видео и документы до 20 МБ скачиваются; больше — пометка «слишком большой».

## 4. Ответ из ленты

Касание сообщения → «В Telegram» (или экран чата — строка ввода сразу пишет в этот чат). Над строкой ввода —
«→ Telegram BY · имя». Отправить = подтвердить: ответ уходит от вашего имени, в группе — ответом на то
сообщение. Под ответом — «отправляется…», затем «✓ в Telegram» или «не отправлено · Повторить».
Обычный «Ответить» остаётся заметкой себе и наружу не уходит.

## Проверка

- ⋮ → «Система»: оба аккаунта «работает», сигнал не старше минуты.
- Написать себе с другого аккаунта → сообщение в ленте за несколько секунд.
- Сообщение в группе из папки «Stream» — в ленте; в группе вне папки — нет.
- Добавить группу в папку → её сегодняшние сообщения появляются.
- Ответить из ленты → собеседник получил ответ от вашего имени.
- `sudo docker compose stop tg-by` → через 5 минут в ленте «Telegram BY: молчит» → `start` → «снова работает»,
  пропущенное догоняется.

## Обслуживание

- Журнал шлюза: `cd /srv/stream/app/deploy && sudo docker compose logs --tail 100 tg-by`.
- Сбросить вход: `sudo rm /srv/stream/tg/by/by.session && sudo docker compose restart tg-by`, затем снова п. 2.
- Указатели прочитанного — `/srv/stream/tg/<аккаунт>/pointers.json`; удалить — шлюз начнёт каждый чат «с сегодня».
