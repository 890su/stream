# Telegram BY и PL — подключение ботов

У каждого аккаунта свой бот: «Stream BY» и «Stream PL». Бот приносит переписку в ленту и отправляет ответы из
ленты от имени аккаунта (`CONCEPT.md` §8.2, `docs/plans/2026-11-17-p11-telegram.md`). Боты работают внутри
сервера Stream: отдельных контейнеров и входа на сервере нет. Premium не нужен.

## 1. Создать двух ботов (один раз)

В Telegram откройте @BotFather (с любого своего аккаунта):

1. `/newbot` → имя `Stream BY` → имя пользователя, например `что-то_by_bot` → BotFather пришлёт **токен**.
2. `/mybots` → этот бот → **Bot Settings → Business Mode → Turn on**: без этого бота нельзя подключить к аккаунту.
3. Там же **Bot Settings → Group Privacy → Turn off**: иначе в группах бот видит только команды, а не всю переписку.
4. То же для `Stream PL`.

Токен — секрет: не пересылайте его в чаты и не кладите в файлы проекта.

## 2. Токены на сервер

```bash
sudo nano /srv/stream/.env
```

Добавить две строки (свои токены):

```
STREAM_TG_BY_BOT_TOKEN=123456789:AA...
STREAM_TG_PL_BOT_TOKEN=987654321:AA...
```

Затем перезапустить Stream (или попросить агента выложить заново):

```bash
cd /srv/stream/app/deploy && sudo docker compose up -d
```

На экране «Система» (⋮ → «Система: источники и отправки») появится «Telegram BY — нужен вход: подключите @…».

## 3. Подключить бота к аккаунту

На белорусском аккаунте: **Настройки → Telegram для бизнеса → Чат-боты** → ввести имя бота BY → выбрать, к каким
чатам у него доступ (например, «все личные чаты» и исключения), и разрешить отвечать на сообщения.
Польский аккаунт — бот PL.

Сразу после этого в ленте: «Telegram BY: подключён аккаунт «…» — подтвердите на экране «Система»». Откройте
⋮ → «Система» → «Подключения Telegram» → **Принять**. До подтверждения бот ничего не читает и не отправляет:
подключить бота может любой, кто знает его имя, — чужие подключения отклоняйте.

## 4. Группы

Добавьте бота своего аккаунта в рабочую группу участником (лучше после шага 3). Группа читается, пока подключение
того, кто добавил бота, принято. Бот виден в группе как участник «Stream BY / PL». Если бота добавил кто-то
другой, его сообщения не читаются — в ленте появится об этом заметка.

## Что попадает в ленту

- Личные чаты, к которым у бота есть доступ (настраивается в Telegram, шаг 3). Лишний чат в Stream: открыть его
  (касание заголовка «Telegram BY · имя») → «Не отслеживать»; вернуть — ⋮ → «Система» → «Не отслеживаются».
- Группы, куда добавлен бот.
- Только новое: старую переписку Telegram ботам не отдаёт. Если сервер был недоступен до суток, пропущенное дойдёт.
- Голосовые, фото, видео и документы до 20 МБ скачиваются; больше — пометка «слишком большой».
- Правка в Telegram — правка поверх исходника; удаление — пометка «удалено в Telegram».

## Ответ из ленты

Касание сообщения личного чата → «В Telegram» (или экран чата — строка ввода сразу пишет в этот чат). Над
строкой ввода — «→ Telegram BY · имя». Отправить = подтвердить: ответ уходит от имени аккаунта, ответом на это
сообщение. Под ответом — «отправляется…», затем «✓ в Telegram» или «не отправлено · Повторить».

- **Окно 24 часа:** бот отвечает только там, где клиент писал за последние сутки. Иначе строка ввода
  предупреждает «окно 24 часа закрыто» — ответьте в Telegram (кнопка «В Telegram» в строке чата).
- **В группах** из ленты не отвечаем: бот писал бы от своего имени.
- Обычный «Ответить» остаётся заметкой себе и наружу не уходит.

## Проверка

- ⋮ → «Система»: Telegram BY и PL — «работает», подключения — «принято».
- Написать себе с другого аккаунта → сообщение в ленте за пару секунд.
- Сообщение в группе с ботом — в ленте.
- Ответить из ленты → собеседник получил ответ от вашего имени.
- Отключить бота в Telegram → «Telegram BY: нужен вход» в ленте.

## Если что-то не так

- «токен бота не принят» — проверить токен в `/srv/stream/.env`, перезапустить Stream.
- «включите Business Mode у @…» — шаг 1.2.
- В группе бот ничего не пишет в ленту — проверить Group Privacy (шаг 1.3): после смены настройки удалите
  бота из группы и добавьте снова.
- Журнал сервера: `cd /srv/stream/app/deploy && sudo docker compose logs --tail 100 stream`.
