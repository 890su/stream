Статус: **обсуждение**. Ничего не делается, пока не согласовано; после согласования — правка `CONCEPT.md`,
затем план шага в `docs/plans/`. В скобках — с каким шагом связано и что предлагается.

- [ ] **Две панели: «Лента» и «Задачи».** Слайд справа налево — задачи, слева направо — обратно в ленту.
  Лента — разговоры, сообщения, логи. Строка ввода всегда внизу, в обеих панелях. (Шаг 5)
  - Предложение: в панели «Задачи» отправленное сообщение по умолчанию получает метку `#задача`
    (снимается одним касанием).
  - ❓ Конфликт жестов: сейчас смахивание влево по сообщению открывает его действия, а смахивание влево по
    экрану должно открывать задачи. Предложение — смахивание по экрану переключает панели, действия над
    сообщением — только долгим нажатием (и «⋯» / правой кнопкой на компьютере).
- [ ] **Кнопка фильтров и параметров** — одна для обеих панелей. (Шаг 4)
  - Лента: быстрые фильтры «Все», «По темам», «Перейти к дате», «По контакту», «По проекту / задаче», по
    метке; параметры отображения (группировка, архив, плотность).
  - Задачи: фильтры по проекту, статусу, сроку, метке.
  - Предложение: кнопка в верхней панели справа, рядом с ⋮; выбранные фильтры видны полоской под заголовком.
- [ ] **Подсказка меток при вводе.** Над строкой ввода — неактивные метки, подобранные по частоте
  употребления и по набираемому тексту; касание включает. При высокой уверенности метка включается сама, её
  видно и можно выключить. (Сначала без ИИ, затем шаг 3)
  - Предложение: первая версия — на телефоне, без сети и ИИ: частота меток + слова-признаки из примеров
    `registry/intents/*.yaml`. Порог автовключения — данные в `registry/capture.json`. Принятые и снятые
    подсказки копятся как обучающие примеры.
- [ ] **Метки с переменными.** Например, `#расход` с полями «сумма», «валюта», «клиент». Значения
  заполняются при разборе и уходят в коннектор. (Шаг 3)
  - Предложение: метка с переменными = цель (`registry/intents/`), переменные = её поля
    (`registry/fields.yaml`). Значения, введённые владельцем, — интерпретация с `author: owner` (контракт уже
    есть). Это объединяет «теги» и «поля» из `CONCEPT.md` §2.2 — нужно решение.
- [ ] **Просмотр разбора сообщения.** Открыть сообщение и увидеть, как оно классифицировано: цель, метки,
  поля, уверенность, действие; поправить любое поле или метку. Правка — новая версия интерпретации.
  (Шаг 3–4; «верно» / «исправить» из `CONCEPT.md` §5)
- [ ] **Действия по сообщению** — расширение панели действий: создать задачу, напоминание, уведомление,
  сообщение контакту, перевести, поставить задачу на выполнение ИИ, другое. (Шаги 3, 5, коннекторы)
  - Предложение: список действий — данные в реестре (операции коннекторов), а не код. Сообщение контакту —
    класс риска B/C: только после «да».
- [ ] **Темы.** Сообщения группируются в темы; неактуальная тема помечается архивной и сворачивается,
  из архива её можно вернуть. (Шаг 4)
  - Предложение: первая версия тем — цепочки ответов (`reply_to` уже есть), затем темы от ИИ (шаг 3).
    Архив темы — событие в журнале, как архив сообщения; потребует нового `kind` (`topic_change`) —
    изменение контракта, запись в `decisions.md`.

Предлагаемый порядок (по пользе и зависимостям): фильтры и «перейти к дате» → подсказка меток без ИИ →
панель задач (шаг 5) → темы из ответов → разбор и метки с переменными (шаг 3) → действия по сообщению.
