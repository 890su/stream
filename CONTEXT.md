# Stream — личная лента событий с ИИ-обработчиком

## Суть

Одна лента, куда всё падает как есть: голос, текст, фото, «Поделиться», Telegram BY и PL, звонки и SMS.
Система сама раскладывает поток по задачам, расходам, заявкам и заметкам; владелец не ведёт списки. Основа —
неизменяемый журнал событий, над ним пересчитываемые слои (нормализация → разбор → задачи и действия). Один
пользователь — владелец, ввод с телефона на Android. Источник истины — `CONCEPT.md` (читать нужные разделы).
Связанные проекты: `../naserwis-pl` — бизнес, ради которого заявки и оферты; `../icrm` — своя CRM, позже коннектор.

## Сейчас (2026-11-20)

Работает на https://stream.sekond.pl, ветка `main` (с 2026-11-20; `install.sh main`): журнал, PWA с офлайн-очередью и SSE;
экран «Беседы · Задачи» (Лента — из ⋮), фильтры слева, подробности справа; задачи с ролями и разбором ИИ
(Claude Haiku 5.5, `triage-ai-v6`); звонки и SMS (Kotlin, `deploy/PHONE.md`); Telegram-боты BY и PL
(`deploy/TELEGRAM.md`); Viber через рабочий стол агентов (`deploy/DESKTOP.md`); WhatsApp PL связанным устройством
(Baileys, `deploy/WHATSAPP.md`). Нет: голос → текст (шаг 2), разбор по целям (шаг 3), бот задач и зеркала (П14,
3–7). Открытое и проверки владельца — `PLAN.md`.

## Запуск и выкладка

`pnpm install`, `.env` по `.env.example` (`STREAM_OWNER_TOKEN` ≥ 32 символов), `pnpm start`
(http://127.0.0.1:3790; `PORT`, `DATA_DIR` — переопределить). Проверки: `pnpm test`, `pnpm typecheck`.
Новый модуль `web/*.js` — в `VERSIONED` в `src/server/static.ts` и `web/sw.js` (проверяет тест).

Агент сам коммитит, пушит и выкладывает каждую правку: srv-150 (192.168.0.149), `/srv/stream`,
`sudo -n bash /srv/stream/app/deploy/install.sh [ref]`; проверка — https://stream.sekond.pl/healthz.
Секреты — только `/srv/stream/.env`. Репозиторий публичный: https://github.com/890su/stream.

## Правила

1. **Исходник неизменяем.** Журнал только дополняется; нет UPDATE/DELETE для событий. Исправление — новое событие.
2. **Производное пересчитываемо.** Слой выше событий можно собрать заново; запись хранит обработчик, версию, модель.
3. **Четыре точки расширения:** источник, цель, коннектор, автоматизация. Иначе — изменение ядра и `decisions.md`.
4. **Данные вместо кода.** Цели, поля, пороги, шаблоны — в `registry/`; нет условий под клиента, сервис, фразу.
5. **Правило трёх.** Автоматизация — после того, как ситуация встретилась трижды.
6. **Коннектор слеп.** Получает действие по контракту, возвращает результат; ленту не читает, ИИ не зовёт.
7. **Задачи — у себя, внешнее — зеркало.** Внешний менеджер получает копию через коннектор.
8. **Идемпотентность.** У события и действия есть ключ; повтор не создаёт дубль и не шлёт второе сообщение.
9. **ИИ за одним интерфейсом** `interpret(event, context) → Interpretation`; провайдер — настройка.
10. **Один процесс, одна база.** Без микросервисов, очередей и векторных баз без измеренной причины.
11. **Эталонный набор.** Смена модели или инструкции прогоняется по `golden/`.
12. **Шаг = польза.** Следующий шаг — после недели использования предыдущего.
13. **Сначала концепция, потом код.** Меняется замысел — сначала `CONCEPT.md`, новые решения — `decisions.md`.
14. **Простая доработка.** Один файл — одна задача (до ~300 строк), заголовок-комментарий на английском; новая
    возможность — новым файлом; поведение покрыто тестами.
15. **Система отдельно от содержания.** В git — только код, контракты, правила, общие словари и вымышленные
    примеры. Сообщения, клиенты, контакты, телефоны, семья, деньги — в `data/` и `*.local.*`, не в git.

Текст для пользователя (интерфейс, вопросы, сводки) — по-русски; код, идентификаторы, коммиты — по-английски.
После работы — обновить `PLAN.md`. `ROADMAP.md` не править без просьбы. Не читать `.library/`, `data/`,
`archive/`, `node_modules/`, секреты; соблюдать `.aiignore` и `.rai.yaml`.
