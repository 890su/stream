# Менеджер задач с ИИ-ассистентом — ТЗ и логика работы

> Статус: **на согласовании** (2026-11-19). Написано с чистого листа, без оглядки на нынешний код: сначала —
> каким должен быть удобный менеджер, потом — сверка с тем, что есть в Stream, и план переделки (отдельный документ).
> После утверждения: правка `CONCEPT.md` (§2.8–§2.11, §5), запись в `decisions.md`.

## 1. Зачем

Владелец ведёт работу в переписке: два Telegram, почта, звонки, свои заметки, рабочие группы с напарниками.
Дела рождаются в разговоре и в нём же теряются: обещал — забыл, поручил — не проверил, проект тихо застыл,
сделанное не попало в отчёт и счёт.

Нужен **ассистент, который ведёт дела**: следит за перепиской, замечает просьбы и обещания, ставит задачи,
следит за выполнением, делает сам всё, что может, остальное готовит к одному касанию, заполняет отчёт и
отдаёт его в учёт. Менеджер задач — его окно: одно место, где видно всю ситуацию.

**Цель:** больше сделанного при меньшем внимании и полный контроль — в любой момент за 5 секунд понятно, что
горит, что делать сейчас, кто кому что должен и как идут проекты.

## 2. Мерки удобства (по ним проверяется каждое решение)

1. **«За рулём».** Любое частое действие — одна фраза или одно касание, без чтения мелкого текста и без форм.
2. **Ничего не докручивать.** Нет обязательных полей, ручной сортировки, тегирования, выбора проекта. Всё это
   делает ИИ; человек только поправляет, если ИИ ошибся.
3. **Ничего не теряется.** У каждой просьбы, обещания и сообщения есть итог; всё без итога видно и всплывает само.
4. **Пять секунд.** Открыл — сразу видно главное, без переходов. Подробности — по касанию.
5. **ИИ делает, человек решает.** Наружу (клиенту, напарнику, в учёт) уходит только то, на что сказано «да»; по
   мере доверия «да» можно выдать заранее для шаблонных случаев.
6. **Тишина по умолчанию.** Система прерывает только когда без человека дело сорвётся; остальное ждёт пульта
   и сводки.

## 3. Цели, не-цели, анти-цели

**Цели:** пульт ситуации; задачи из переписки без ручного ввода; слежение за обещаниями и поручениями;
ИИ-исполнитель; проекты с динамикой; отчёт по выполненному; передача в учёт.

**Не-цели (сейчас):** диаграмма Ганта, учёт рабочего времени по минутам, автоматическое расписание всего дня
(как Motion), совместное редактирование задач напарниками в приложении (напарники работают через бота).

**Анти-цели — провал, даже если всё работает:**
- владелец снова ведёт списки руками или должен раз в день «разгребать» систему дольше 5 минут;
- шум: напоминания, которые игнорируются, — значит, система не умеет молчать;
- ИИ сделал наружу то, что владелец не одобрял;
- «красивые доски», которые надо поддерживать, вместо ответа «что делать сейчас».

## 4. Сущности

Человек видит пять понятий: **Дело, Обещание, Проект, Люди, Отчёт.** Остальное — внутри.

### 4.1 Дело (задача)

Одно, что нужно довести до результата. Может иметь чеклист пунктов.

| Поле | Кто заполняет | Зачем |
|---|---|---|
| Название | ИИ (владелец может переименовать — тогда ИИ его не трогает) | понятно без открытия |
| Чьё | ИИ: **моё / поручено / жду / команда** (см. 4.2) | в какой блок пульта |
| Исполнитель, проверяющий, автор | ИИ по переписке | кто делает, кто отвечает |
| Проект | ИИ по источнику и смыслу | динамика и учёт |
| Срок | ИИ из текста («завтра», «до пятницы») или нет | очередь |
| Важность | вычисляется (4.5), не вводится | порядок |
| Следующий шаг | ИИ (одна фраза: «позвонить и уточнить адрес») | что делать, не открывая |
| Источники | сообщения, звонки, письма | всегда видно, откуда дело |
| Что ИИ может сделать | ИИ (5.3) | значок 🤖 / ✋ / 👤 |
| Отчёт | ИИ из переписки + подтверждение | учёт и счёт |

**Срок и «когда браться» — разное:** у дела может быть `не раньше` (отложено до даты) и `срок`. Отложенное
не видно до своей даты и возвращается само.

### 4.2 Чьё дело — четыре положения

| Положение | Смысл | Где на пульте |
|---|---|---|
| **Моё** | делаю я | «Сейчас» / «Дальше» |
| **Поручено** | делает другой, отвечаю я | «Слежу» |
| **Жду** | кто-то обещал мне (ответ, деньги, адрес, деталь) | «Слежу» |
| **Команда** | дело между другими людьми, я только наблюдаю | только в «Команде» |

Статусы внутри (новое, в работе, на проверке, готово, отменено, отложено) человек почти не трогает: «Готово»
одним касанием, остальное меняет ИИ по переписке и спрашивает, если сомневается.

### 4.3 Обещание

Любая договорённость со сроком в переписке — **своя или чужая**: «завтра пришлю счёт» (моё), «вечером скину
адрес» (жду), «в понедельник выйду на объект» (поручено). Обещание — это дело с цитатой и датой; у чужого
обещания есть **таймер слежения** (6). Обещания без даты получают дату по умолчанию из настроек (например,
«скоро» = 2 рабочих дня).

### 4.4 Проект

Контейнер дел; у дела ровно один проект (или «Без проекта»). Два вида:
- **Поток** — работа без конца (удалёнка, выезды PL): дела приходят и уходят, мерится поток.
- **Проект с целью** — сайт, переезд, запуск: этапы, бэклог идей и **всегда один следующий шаг**.

У проекта: название, вид, статус (активен / на паузе / завершён), владелец, источники по умолчанию (этот чат →
этот проект), зеркало в CRM (опционально).

### 4.5 Важность — вычисляется, не вводится

Порядок в любом списке — одна формула (веса — настройка, не код):
1. **Горит** — просрочено, срок сегодня, клиент ждёт ответа дольше порога, чужое обещание просрочено.
2. **Деньги** — дело ведёт к оплате (заявка, счёт, долг).
3. **Блокирует других** — напарник ждёт моего решения.
4. **Срок ближе** — раньше выше.
5. **Давно не двигалось** — выше, чтобы не застывало.

Владелец может «закрепить наверху» одно дело на сегодня — это единственная ручная сортировка.

## 5. Пульт — главный экран

Открывается по умолчанию. Пять блоков, каждый — заголовок со счётчиком и до 3–5 строк; «ещё N» раскрывает
список. Пустой блок сворачивается в одну строку «✓ Слежу — всё по плану».

```
┌ Пульт ───────────────────── ср 19.11 ┐
│ 🔥 Горит                          2  │
│  ○ Ответить Андрею по сетке   ждёт 5ч│
│  ○ Счёт ООО «…» — срок сегодня     ✋ │
│ ▶ Сейчас (моё)                    4  │
│  ○ Позвонить, уточнить адрес      👤 │
│  ○ Настроить роутер у Лены   ☑1/3 12:00│
│ 👁 Слежу                     5 · 1 ⚠ │
│  Паша: камеры на объекте  молчит 3 дн✋│
│  Клиент: адрес — обещал вчера     ✋ │
│ 🤖 ИИ подготовил                  6  │
│  [Просмотреть и отправить]           │
│ 📊 Проекты                           │
│  Удалёнка BY  ↑6 сделано · 3 откр    │
│  Сайт         ⚠ стоит 9 дн · шаг: … │
│ ⏭ Дальше                          7  │
└──────────────────────────────────────┘
  [ сказать / написать ................ 🎤 ]
```

### 5.1 Блоки

| Блок | Что попадает | Порядок | Счётчик |
|---|---|---|---|
| **🔥 Горит** | моё и слежу: просрочено; срок сегодня; беседа ждёт моего ответа дольше порога; чужое обещание просрочено | важность | всего |
| **▶ Сейчас** | моё на сегодня: срок сегодня/завтра, следующие шаги проектов, закреплённое; максимум — **лимит дня** (по умолчанию 5) | важность | всего / лимит |
| **👁 Слежу** | поручено + жду; отдельно ⚠ — молчат дольше таймера | ближайший таймер | всего · ⚠ |
| **🤖 ИИ подготовил** | черновики и предложения, ждущие «да» (5.3) | важность дела | всего |
| **📊 Проекты** | активные проекты: динамика за 7 дней и следующий шаг (7) | сначала проблемные | — |
| **⏭ Дальше** | моё без срока на сегодня, по важности; отложенное не показывается | важность | всего |

**Правила однозначности:**
- Дело стоит **ровно в одном** из блоков «Горит / Сейчас / Слежу / Дальше» — первое подходящее сверху вниз.
  «ИИ подготовил» — список *действий*, не дел: дело остаётся в своём блоке со значком ✋.
- «Горит» входит в лимит дня первым. Что не влезло в «Сейчас» — в «Дальше» с пометкой «не влезло сегодня»;
  утренняя сводка называет, что не влезло.
- Отложенное до даты и дела «Команды» на пульте не показываются (только «Команда» — в «Слежу» с ⚠, если клиент
  ждёт ответа дольше порога).

**Разобрать** — отдельно не показывается, пока ИИ справляется: всё, в чём ИИ не уверен, приходит как вопрос в
«ИИ подготовил» («О каком деле?», «В какой проект?», «Это задача?»). Неразобранное старше порога — в «Горит».

### 5.2 Строка дела

Одна строка: кружок «Готово» · название · с кем · прогресс чеклиста · срок или таймер · значок ИИ.
- **Касание по кружку** — «Готово» (с «Вернуть» несколько секунд).
- **Смахивание вправо** — «Готово»; **влево** — «Когда?» (сегодня / завтра / на неделе / дата / «жду…»).
- **Касание по строке** — подробности: следующий шаг, источники (последняя реплика видна сразу), чеклист,
  люди, отчёт, история, кнопки действий ИИ.
- Значки: 🤖 ИИ уже что-то сделал; ✋ ИИ подготовил, нужно «да»; 👤 нужен я лично.

### 5.3 Блок «ИИ подготовил» — очередь одобрения

Карточки по одной (как разбор почты): что ИИ предлагает, для какого дела, текст черновика.
Кнопки: **«Да»** · **«Поправить»** (голосом или текстом) · **«Не надо»**. Похожие карточки можно одобрить пачкой
(«Напомнить всем трём»). Каждое «да» / правка — обучающий пример (9).

## 6. ИИ-ассистент: как работает

### 6.1 Циклы

| Когда | Что делает |
|---|---|
| **На каждое сообщение** (после паузы в беседе) | находит просьбы, обещания, сроки, деньги, «сделано»; создаёт дела, пункты, обещания; привязывает к делу и проекту; обновляет следующий шаг; закрывает или предлагает закрыть |
| **Каждый час** | проверяет таймеры (6.2), сроки и тишину; переносит в «Горит»; готовит напоминания |
| **Утро** | план дня: собирает «Сейчас» в пределах лимита, говорит, что не влезло; сводка (8) |
| **Вечер** | итог дня, незакрытые отчёты, вопросы без ответа, застывшие проекты; сводка (8) |
| **Неделя** | обзор проектов: динамика, застывшее, «следующий шаг, пауза или закрыть?» |

### 6.2 Слежение — лестница по таймеру

Для каждого дела «поручено» и «жду» (сроки — настройка, по видам дел):

| Момент | Что происходит |
|---|---|
| Поручил / услышал обещание | дело в «Слежу», таймер = срок или срок по умолчанию |
| Нет «принял» за N часов (поручение) | ✋ черновик «Паша, видел задачу?» |
| Срок наступил, ответа нет | ✋ черновик напоминания исполнителю; строка ⚠ |
| +1 рабочий день | дело в «Горит» |
| +3 дня | вопрос владельцу: «Переназначить, перенести или снять?» |

**Что считается ответом:** любое сообщение исполнителя в связанной беседе, отметка в боте, слово «сделал»
(ИИ предлагает закрыть: «Готово?»). Ответ сбрасывает таймер, «сделал» переводит дело в «на проверке» — проверка
приходит владельцу одной карточкой.

### 6.3 Что ИИ делает сам, что готовит, что оставляет

| Уровень | Что | Примеры |
|---|---|---|
| **🤖 Сам** (внутри системы, обратимо) | всё, что не уходит наружу | разобрать сообщение, создать дело, пункт, обещание; срок из текста; проект; следующий шаг; заполнить отчёт черновиком; найти в переписке адрес, телефон, сумму; объединить дубли; поднять застывшее |
| **✋ Готовит к «да»** (наружу) | сообщения людям, изменения в учёте | ответ клиенту; поручение напарнику; напоминание о сроке; отчёт в CRM; счёт в учёт |
| **👤 Только человек** | решения и физическая работа | приехать, позвонить, договориться о цене, решить спор |

**Лестница доверия:** вид действия «✋» переходит в «🤖 сам» для шаблонных случаев, когда владелец одобрил его
без правок 20 раз подряд (правило — данные, можно выключить). Счёт ведётся по паре «вид действия × шаблон»
(например, «напоминание о сроке напарнику»), любая правка или «Не надо» обнуляет счёт. Переход и откат видны в
настройках. Действия с деньгами и учётом (счёт, отчёт в CRM) по лестнице не переходят никогда — только «да».

### 6.5 Когда ИИ ошибся или недоступен

| Случай | Что видит и делает владелец |
|---|---|
| ИИ создал лишнее дело | «Не задача» в строке (смахивание или кнопка); сообщение получает итог «без дела»; пример для обучения |
| ИИ пропустил просьбу или обещание | фраза «это задача» / «Паша обещал адрес к вечеру» — или «Сделать задачей» на сообщении |
| Склеил разные дела / разбил одно | «Отдельным делом» на пункте, «В дело…» на деле |
| Сообщение исправили или удалили | дело пересобирается; если уже ушло действие наружу — карточка «Отменить / оставить» |
| Действие наружу ушло ошибочно | отменяемое (своё сообщение в Telegram) — «Вернуть»; необратимое (письмо, счёт) — помечается заранее на карточке «✋ необратимо» |
| ИИ недоступен или кончился лимит | пульт работает на последних данных; в «Горит» строка «Не разобрано N сообщений», таймеры слежения работают без ИИ (они — правила, не ИИ) |

### 6.4 Когда ИИ спрашивает

Только при сомнении, которое меняет дело: к какому делу, в какой проект, задача ли это, закрыть ли. Вопрос — карточка
в «ИИ подготовил» с готовым вариантом ✓ и 2–3 альтернативами; без ответа за день — в вечернюю сводку, ИИ
оставляет свой вариант. Ни одного вопроса без варианта по умолчанию.

## 7. Проекты и динамика

На пульте и в проекте — одни и те же числа за 7 дней:

| Показатель | Как считается |
|---|---|
| **Сделано** | дел закрыто за 7 дней, стрелка к прошлым 7 дням |
| **Пришло** | новых дел за 7 дней |
| **Открыто** | сейчас открыто, из них просрочено |
| **Стоит** | дней без движения (закрытие, новое дело, сообщение по делу) |
| **Следующий шаг** | одно открытое дело-шаг (для проекта с целью — обязательно) |
| **Деньги** | (с учётом) выставлено / оплачено / ждёт оплаты за период |

**Здоровье:** 🟢 есть шаг и движение; 🟡 нет шага или стоит дольше `stale_days`; 🔴 есть просроченное «горит».
Проблемные проекты — первыми.

Проект открывается списком по разделам (для проекта с целью: Идеи · Следующее · В работе · Готово) и лентой
событий проекта (что произошло за неделю — текстом, собирает ИИ).

## 8. Сводки

Сводка — тот же пульт, отправленный по расписанию (уведомление, Telegram), с кнопками на каждую строку.
- **Утро:** «Сегодня 4 дела, горит 2, жду 5, ИИ подготовил 6. Главное: …». Кнопка «Отправить всё подготовленное».
- **Вечер:** сделано за день; что не сделал из «Сейчас» (перенести на завтра — одной кнопкой); незаполненные
  отчёты; вопросы без ответа; кто молчит.
- **Неделя:** проекты — динамика, застывшие, решения «шаг / пауза / закрыть».
Сводку можно прослушать (озвучка текста) — мерка «за рулём».

## 9. Голос и одна фраза

Строка ввода внизу пульта понимает команды и обычный текст одинаково (ИИ решает, команда это или запись):

| Фраза | Результат |
|---|---|
| «Перенеси звонок Анне на пятницу» | срок дела → пятница |
| «Поручи Паше камеры у клиента, до четверга» | дело, поручено, ✋ сообщение Паше |
| «Готово с роутером, полтора часа, 120 злотых» | дело закрыто, отчёт: время и сумма |
| «Что горит?» / «Что у Паши?» | короткий ответ текстом и голосом |
| «Напомни завтра в 9 про счёт» | дело со сроком и напоминанием |
| «Сайт на паузу» | статус проекта |

Ошибка распознавания исправляется так же — фразой («не Анне, а Ане»). Каждая команда показывает итог с «Вернуть».

## 10. Команда и напарники

- Рабочая группа (чат) — тоже исполнитель: «поручить группе», первый ответивший «беру» становится исполнителем.
- Напарники работают **без приложения**, через бота: получают поручение с кнопками «Принял / Не могу», напоминания,
  отчёт по выполнению («Сделал» → фото, время, материалы).
- Владелец видит «Команду»: дела между другими людьми — не в своих списках, но в динамике проекта и с ⚠, если
  клиент ждёт.

## 11. Отчёт и учёт

- При «Готово» ничего не спрашивается. ИИ заполняет отчёт из переписки и сообщений исполнителя: дата, время,
  работы, материалы, сумма, валюта. Поля — по виду дела (данные), не форма.
- Отчёт с пробелами — в «Не учтено» и вечерней сводке; дозаполняется фразой.
- Полный отчёт → ✋ «Отправить в учёт» (CRM, затем счёт). Статус оплаты возвращается из учёта и виден в деле
  и в «Деньгах» проекта. ❓ Куда именно и как выставляются счета в BY и PL — отдельное решение (13).

## 12. Уведомления — когда система прерывает

Прерывает (push) только:
- клиент или напарник ждёт моего ответа дольше порога;
- срок моего дела через час / наступил (для дел со временем);
- исполнитель не принял срочное поручение.
Всё остальное — на пульте и в сводках. Тихие часы и дневной лимит push — настройка. Если push игнорируются
неделю, система предлагает сократить их вид.

## 13. Практики эффективности — что заложено и каким механизмом

Принцип: практика работает, только если её делает система, а не дисциплина владельца (§1 концепции: владелец не
ведёт списков). Поэтому каждая практика — механизм, а не совет.

| Практика | Суть | Механизм здесь |
|---|---|---|
| **GTD: сбор и разбор** (Аллен) | всё из головы — во входящие, у каждого — итог | лента собирает всё; ИИ даёт итог каждому сообщению; «не разобрано» всплывает в «Горит» |
| **GTD: следующее действие** | у дела — конкретный физический шаг | поле «следующий шаг» одной фразой у каждого дела и проекта |
| **GTD: «Жду»** | чужие обещания — тоже список | «Слежу» с таймерами и лестницей напоминаний (6.2) |
| **GTD: еженедельный обзор** | раз в неделю пройти проекты | недельная сводка с решениями «шаг / пауза / закрыть» (8) |
| **MIT / «съешь лягушку»** | 1–3 главных дела дня — первыми | порядок по важности, «закрепить наверху» одно дело; утро называет главное |
| **Лимит незавершённого (WIP, канбан)** | меньше начато — больше закончено | лимит дня «Сейчас» (5); не влезшее — явно «не влезло» |
| **Эйзенхауэр** | срочное ≠ важное | формула важности (4.5): «горит» и «деньги / блокирует» — разные оси |
| **Правило двух минут** | короткое — сразу | ИИ делает короткое сам (🤖); на ✋ — одно касание «Да» |
| **Пакетная обработка** | похожее — пачкой | «ИИ подготовил»: одобрить похожие карточки разом; сводки вместо потока push |
| **Закрытие петель (эффект Зейгарник)** | незакрытое отвлекает | у каждого обещания — итог; вечер переносит несделанное одной кнопкой — голова пустая |
| **Ритуал завершения дня** (Sunsama, Ньюпорт) | вечером закрыть день и план на завтра | вечерняя сводка: сделано, перенос, отчёты, кто молчит |
| **Тайм-боксинг** | дело получает время в календаре | у дела со временем — блок в календаре (зеркало), не обязательно |
| **Делегирование с контролем** (принцип «проверяющий») | поручил — проверь | у поручения — проверяющий и «на проверке»; «Сделал» → карточка проверки |
| **Тишина / глубокая работа** | прерывания — дорогие | push только по 3 случаям (12), тихие часы, лимит |
| **Правило трёх** (концепция) | автоматизировать после трёх повторов | лестница доверия ИИ (6.3), шаблоны действий |

Чего сознательно нет: ручных приоритетов P1–P4, контекстов @дом/@офис (их заменяют проект и формула важности),
помодоро — это личные приёмы, не работа системы.

## 14. Допущения (проверить на использовании)

| # | Допущение | Если неверно |
|---|---|---|
| A1 | Клиент / напарник / личное различаются по чату и проекту источника | нужен справочник контактов (П7) раньше |
| A2 | Время и «рабочие дни» — по часовому поясу и календарю владельца; у напарника — его тихие часы | напоминания в ночь для BY / PL |
| A3 | «Деньги» важнее «блокирует других» | поменять веса (это настройка) |
| A4 | Напарники не ставят приложение, им хватает бота | понадобится доступ напарникам к пульту |
| A5 | При поручении группе двое «беру» — исполнитель первый, второй получает «уже взял Паша» | — |
| A6 | Владелец разбирает «ИИ подготовил» 1–2 раза в день, не постоянно | ✋ копятся — сводка должна напоминать |

## 15. Открытые вопросы владельцу

1. Лимит дня для «Сейчас» — 5 по умолчанию? (Больше — список перестаёт быть планом.)
2. Пороги «ждёт ответа»: клиент — 2 часа, напарник — 4 часа, личное — сутки?
3. Срок по умолчанию для обещания без даты — 2 рабочих дня?
4. Учёт и счета: куда отдаётся отчёт (Планфикс, польская бухгалтерия, своя таблица оплат) — решаем на этапе учёта.
5. Сводки — куда: уведомление приложения, Telegram-бот или оба?

## 16. Подходы (рассмотрено)

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **А (выбран)** | **Пульт + ИИ-исполнитель на каждом деле**; сводки — тот же пульт по расписанию | ситуация видна в любой момент; ИИ встроен в каждое дело; сводка бесплатно | динамика проектов вначале простая (числа, без графиков) |
| Б | ИИ-секретарь сводками, экран вторичен | проще всего | нет обзора в любой момент — нет контроля |
| В | Доски проектов, как в Планфиксе | привычно для команды | надо поддерживать руками; теряется «что мне делать сейчас» |

## 17. Как проверить, что удобно

| Мерка | Как мерим | Цель |
|---|---|---|
| Пять секунд | открыть пульт → назвать главное дело | без прокрутки |
| Ничего не докручивать | ручных правок полей ИИ за неделю | < 10% дел |
| Ничего не теряется | сообщений без итога старше часа | 0 |
| Слежение | просроченных чужих обещаний, о которых владелец не знал | 0 |
| Тишина | push в день / из них открыто | ≤ 5 / ≥ 70% |
| ИИ полезен | доля «✋» одобрено без правок | ≥ 80% |
| Разгребание | время в «ИИ подготовил» в день | ≤ 5 мин |

## 18. Решения исполнителя (не владельца)

Вид экранов на компьютере (пульт колонкой слева), анимации, формулировки карточек, формат хранения
настроек, точные веса формулы важности — по этим мерам, с проверкой на владельце.
