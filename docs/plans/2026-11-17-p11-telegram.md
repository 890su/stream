# П11 — Telegram BY и PL в ленте, ответ из ленты; экран «Система»

Концепция: `CONCEPT.md` §8.2, §5 («Экран „Система“»). Решения: `decisions.md` 2026-11-17 «Telegram: шлюз на
каждый аккаунт…», «Какие чаты Telegram в ленте…», «Учёт автоматизаций — экран „Система“…».

## Зачем

Заявки, договорённости с компаньонами и передача работы подрядчикам идут в Telegram двух аккаунтов и нигде не
сводятся; просьбы жены и друзей теряются среди рабочего. Лента собирает всё в одно место, разбор (шаг 3)
раскладывает, ответ уходит из ленты в тот же чат.

- **Цель:** каждое сообщение отслеживаемых чатов обоих аккаунтов — в ленте за секунды, с медиа; ничего не
  теряется при простое; ответ из ленты — в тот же чат с того же аккаунта; видно, что шлюзы живы.
- **Не цель:** WhatsApp и Viber (следующие пакеты по тому же образцу), черновики ИИ (шаг 3), справочник
  контактов и роли (П7), секретные чаты, рассылки, каналы.
- **Анти-цель:** список «рабочих чатов», который надо вести; сообщение, ушедшее клиенту случайно; шлюз,
  который тихо умер; код входа или сессия в git или в переписке с агентом.

## Подходы

| Подход | Плюсы | Минусы |
|---|---|---|
| **Шлюз на клиентском API (MTProto), по контейнеру на аккаунт** — предлагается | видит всё, что видит владелец: группы, свои сообщения, пересылки; ответ от своего имени | отдельный процесс; вход кодом один раз; правила Telegram против злоупотреблений |
| Бот с бизнес-подключением | официальный путь для бизнеса | без групп и своих сообщений, нужен Premium, окно 24 ч — **не закрывает задачу** |
| n8n + Telegram-узлы | готовые узлы, видно прогоны | узлы — для ботов, не для аккаунта; второй источник правды |
| Чтение уведомлений Android (§8) | без входа на сервере | только пока телефон жив, без истории, без групп в папке, ответ ненадёжен |

**Библиотека:** Telethon 1.45 (Python) — зрелая и поддерживаемая. GramJS отпал: пакет в архиве, разработка
ушла в новый форк (`decisions.md` 2026-11-17 «Шлюз Telegram на Telethon»).

## Устройство

```
Telegram BY ⇄ [контейнер stream-tg-by] ─┐
                                         ├─ HTTPS 127.0.0.1:3790 /api/gateway/telegram/* ─ Stream (один сервер, одна база)
Telegram PL ⇄ [контейнер stream-tg-pl] ─┘
```

- Код шлюза — `gateway/telegram/` этого репозитория (свой образ Python). Шлюз параметризован аккаунтом:
  `TG_ACCOUNT=by|pl`, `TG_API_ID`, `TG_API_HASH`, `STREAM_URL`, `STREAM_GATEWAY_TOKEN`. Owner-токена у него нет.
- Сессия — `/srv/stream/tg/<account>/<account>.session` (папка 700, владелец `stream`), вне git и вне `.env`.
- Вход: владелец получает `api_id` / `api_hash` на my.telegram.org (один на оба аккаунта), затем в терминале
  сервера `docker compose run --rm tg-by login` — сам вводит номер, код из Telegram и пароль 2FA.
- Токены шлюзов `STREAM_TG_BY_TOKEN`, `STREAM_TG_PL_TOKEN` (≥ 32) в `/srv/stream/.env`; `install.sh` дописывает,
  если нет. Токен открывает только `/api/gateway/telegram/*` и только свой аккаунт.

## Сервер: адреса шлюза

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/gateway/telegram/<account>/messages` | пачка сообщений → события; id = UUID из sha256 `tg|<account>|<chat_id>|<message_id>`; повтор → тот же id |
| `PUT` | `/api/gateway/telegram/<account>/media/:sha256` | файл до сообщения (как медиа обычного ввода); предел шлюза — `registry/telegram.json` |
| — | (в `messages` с `edit_date`) | правка в Telegram → `correction` поверх исходного (`data.origin: telegram`) |
| `GET` | `/api/gateway/telegram/<account>/config` | исключённые чаты, имя папки, сутки «сегодня» по местному времени |
| `GET` | `/api/gateway/telegram/<account>/actions?wait=25` | долгий опрос: одобренные `send_message` своего аккаунта |
| `POST` | `/api/gateway/telegram/<account>/actions/:id/result` | итог отправки (`done` + номер сообщения / `failed` + причина) → событие `action_result` |
| `POST` | `/api/gateway/telegram/<account>/pulse` | пульс раз в минуту: состояние, вход, очередь, последняя ошибка |

**Событие** (Event v1, добавления без новой версии): `kind` — `text` / `voice` / `photo` / `file`;
`source: telegram`; `author: me` для своих, `contact:tg:<account>:<user_id>` для чужих;
`payload.data.telegram = { account, chat_id, chat_type (private|group), chat_title, from_name, message_id,
reply_to_message_id?, forward?: { from_id?, from_name?, date }, album_id?, sent_at }`. Проверка — новый
`src/contracts/telegram.ts` по образцу `phone.ts`.

**Пересылка:** если у сообщения `forward` и в журнале есть сообщение того же автора с тем же временем — сервер
пишет его продолжением исходного (`continuation`). Альбом — части одним пузырём (`album_id`).

**Действие ответа:** `connector: telegram_<account>`, `operation: send_message`, `risk_class: C`,
`params: { chat_id, text, reply_to_message_id? }`, `idempotency_key` = id события-ответа. Отправка из строки
ввода в режиме «→ Telegram» создаёт событие-ответ (`author: me`, `payload.data.outbound`) и действие сразу в
статусе `approved` — нажатие «Отправить» и есть подтверждение. Эхо отправленного шлюз узнаёт по номеру
сообщения из результата и второй раз не пишет.

## Шлюз: как читает

1. Старт: вход по сессии; список диалогов; отслеживаемые = личные чаты с людьми − исключения + группы из папки
   «Stream». Для каждого чата — сохранённый номер последнего записанного сообщения (локальный файл состояния).
2. Чат впервые отслеживается → сообщения с местной полуночи. Чат отслеживался → догон с сохранённого номера.
3. Дальше — поток обновлений Telegram; изменение папки или исключений (опрос `config` раз в минуту) → пересчёт
   списка и п. 2 для новых чатов.
4. Номер сообщения сохраняется только после ответа сервера (как указатель в компаньоне телефона).
5. Паузы Telegram (`FLOOD_WAIT`) соблюдаются; при потере входа — пульс «нужен вход», шлюз ждёт, не падает в
   цикл.

## Клиент Stream (PWA)

- Пузырь Telegram: заголовок «Telegram BY · имя» / «группа · автор»; входящие — у левого края, свои — справа;
  подряд из одного чата — одним пузырём. Голос, фото, файлы — как у обычного ввода.
- Экран чата — касание заголовка: вся переписка с чатом (по `chat_id`), строка ввода в режиме «→ Telegram».
- Панель действий: «Ответить в Telegram», «Не отслеживать чат» (подтверждение + «отправить записанное в архив?»).
- Строка ввода в режиме «→ Telegram · имя»: заметная плашка, × — обратно в обычный ввод. Статус под своим
  ответом: «отправляется» → «✓ в Telegram» / «не отправлено — повторить».
- Левая панель: фильтр по источнику (мои, Telegram BY, Telegram PL, телефон).
- Новые модули: `web/tgbubble.js`, `web/chatscreen.js`, `web/system.js` → в `VERSIONED`.

## Экран «Система»

- Строка на каждый источник и коннектор: Telegram BY, Telegram PL, «Stream · телефон» (пульс компаньона — в
  `/api/phone/ping`), позже коннекторы и автоматизации. Состояние: работает / молчит > 5 мин / нужен вход /
  ошибка; последний пульс, последнее сообщение, очередь, ошибки за сутки.
- Журнал действий: что, куда, статус, когда, ошибка; «Повторить» для `failed`.
- Исключённые чаты по аккаунтам — «Вернуть».
- Переходы состояния (пропал, вернулся, нужен вход, отправка не удалась) — служебное сообщение в ленте.
- Данные: таблица `source_status` (последний пульс, не журнал) + действия из таблицы действий.

## Порядок работ

1. Сервер: контракт `telegram`, адреса шлюза, токены, `source_status`, действия `send_message` и их выдача.
2. Шлюз: вход, отбор чатов, «сегодня», догон, поток, медиа, правки, пульс. Проверка на тестовом аккаунте
   Telegram (тестовый сервер Telegram, без настоящей переписки).
3. Лента: пузыри, экран чата, фильтр по источнику, «Не отслеживать».
4. Ответ из ленты: режим «→ Telegram», действие, статус, эхо.
5. Экран «Система».
6. Выкладка: контейнеры `tg-by`, `tg-pl` в `deploy/docker-compose.yml`, `deploy/TELEGRAM.md`; вход владельцем.

## Проверки

- **Сервер** (`node --test`): контракт, повтор без дубля, токен шлюза только на своих адресах и своём
  аккаунте, правка/удаление поверх исходника, связь пересылки, выдача действий долгим опросом, итог действия,
  пульс → переход → служебное сообщение.
- **Шлюз** — чистая логика без сети: отбор чатов, «сегодня» по часовому поясу, догон по указателю, разбор
  сообщения Telegram в тело запроса, исключение эха.
- **Владелец:** вход обоих аккаунтов; личное сообщение и сообщение в группе из папки — в ленте; группа вне
  папки — нет; добавление группы в папку подтягивает сегодняшнее; «Не отслеживать»; ответ из ленты в личку и
  в группу; остановка шлюза → сообщение «Telegram BY молчит» → запуск → догон без потерь.

## Решения исполнителя (можно поправить)

- «Сегодня» — с полуночи часового пояса аккаунта: BY — Europe/Minsk, PL — Europe/Warsaw (`registry`).
- Медиа больше 20 МБ не скачиваются, пишется отметка.
- Удалённое в Telegram в Stream не исчезает, только помечается.
- Шлюз — на Node (GramJS), в том же репозитории и образе.
