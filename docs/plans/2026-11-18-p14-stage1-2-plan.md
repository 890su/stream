# П14, этапы 1–2 — модель задачи с ролями и экран «Беседы»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** задача получает стороны и роли (ответственный, исполнители, контролёр…), разбор их заполняет, а главный
экран — список бесед, отсортированный по тому, кто кого ждёт; «Задачи» выбираются сохранёнными фильтрами.

**Architecture:** изменения задачи — те же `task_change` с новыми необязательными полями (`roles`, `waiting_for`,
`plan`, `remind_at`, `promise`, статусы `review` / `deferred`); старые события читаются через перевод
`assignee` → роли. Беседа — чистая проекция на устройстве (`web/conversations.js`) по ключу канала; состояние и
порядок — по правилам из `registry/conversations.json`. Фильтры задач — данные (`registry/filters.json`) и один
интерпретатор условий (`web/filters.js`). Вид «Дела» и сворачивание сделанного в ленте убираются.

**Tech Stack:** Node 24 (TypeScript без сборки), `node:sqlite`, `node --test`; клиент — ES-модули без сборщика;
разбор — `@anthropic-ai/sdk` (структурированный вывод).

**Spec:** `docs/plans/2026-11-18-p14-conversations-tasks-design.md` (утверждён 2026-11-18). Этапы 3–7 — отдельные планы.

## Global Constraints

- Журнал только дополняется; никаких UPDATE/DELETE событий. Старые `task_change` (с `assignee` / `person`) читаются без миграции.
- Новые поля `task_change` — необязательные: Event остаётся v1 (как `proposed` / `report` / `alternatives`), запись в `decisions.md`.
- Данные вместо кода: пороги состояний бесед, фильтры, шаблоны — в `registry/`; в коде нет условий под людей и фразы.
- Сторона (party) — строка одного из видов: `me`, `ai`, `system`, `tg:<user id>`, `tel:<+цифры>`, `group:tg:<chat id>`, `name:<как назвали>`.
- Текст интерфейса — по-русски; код, идентификаторы, коммиты — по-английски; заголовок-комментарий у каждого нового файла.
- Новый модуль `web/*.js` — в `VERSIONED` (`src/server/static.ts`) и в список `web/sw.js`; удалённый — оттуда же убрать.
- Файл — одна ответственность, ориентир до 300 строк; `web/feed.js` после правок не длиннее, чем сейчас (325).
- Примеры в тестах и документах — вымышленные (правило 15).
- После каждой задачи: `pnpm test`, `pnpm typecheck`; коммит заканчивается строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Выкладка — в задаче 9: push, `ssh -i ~/.ssh/id_ed25519 admin890brain@192.168.0.149 'sudo -n /usr/bin/bash /srv/stream/app/deploy/install.sh step1-journal-capture'`, проверка https://stream.sekond.pl.

## Review Focus

1. **Старые задачи без ролей** (созданы до v2, `assignee: 'person'` с `person: 'Марек'`) должны показываться с исполнителем
   `name:Марек`, ответственным `me` и не пропадать из «Мои». Тест — задача 3.
2. **Один человек в BY и PL** пишет с одним Telegram id: его личные чаты обоих аккаунтов — одна беседа, а ответ уходит
   через аккаунт его последнего входящего. Тест — задача 5 (ключ), задача 7 (получатель).
3. **«Ок» и «спасибо» от клиента** (итог разбора — `chatter`, filed) не делают беседу «ждёт меня». Тест — задача 5.
4. **Неразобранное входящее** (разбор ещё не дошёл, задач нет) делает беседу «ждёт меня» сразу. Тест — задача 5.
5. **Ответ ИИ со стороной, которой нет во входе** (выдуманный `tg:999`) не попадает в журнал: заменяется на `name:` из
   его же текста или отбрасывается. Тест — задача 4.
