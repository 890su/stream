# П10 — Звонки в журнале: компаньон «Stream · звонки» на Kotlin

Концепция: `CONCEPT.md` §8.1. Решения: `decisions.md` 2026-11-17 «Звонки в журнале» и «Компаньон звонков —
отдельное приложение на Kotlin».

## Зачем

После звонка владелец за несколько секунд записывает, о чём был разговор и чем закончился. Звонок и описание
лежат в ленте рядом, описание — продолжение звонка и попадает в тему дела; на шаге 3 его разбирает ИИ.
Сейчас звонки нигде не фиксируются, и договорённости по телефону теряются.

- **Цель:** каждый звонок (входящий, исходящий, пропущенный, отклонённый) в ленте; описание — одним ответом
  из уведомления; ничего не теряется без сети и при убитом фоне.
- **Не цель:** запись разговора, расшифровка, привязка номера к контакту справочника (П7), вечерняя сводка
  (шаг 6), чтение уведомлений других приложений, публикация в Google Play.
- **Анти-цель:** приложение, которое нужно открывать или настраивать снова; уведомления, которые раздражают
  (после каждого пропущенного); токен владельца на телефоне вне Stream.

## Подходы (выбрано 2026-11-17)

| Подход | Плюсы | Минусы |
|---|---|---|
| Tasker / MacroDroid | за вечер, без своего кода | направление и длительность ненадёжны; токен в чужом приложении — **отменено владельцем** |
| **Отдельное приложение на Kotlin** — выбрано | точные данные журнала, своя очередь, Stream не трогаем | два значка на телефоне |
| Stream в оболочке TWA + звонки | один значок | переустановка Stream, проверка «Поделиться» и ярлыков заново; позже, код звонков переносится |
| Своя оболочка на WebView | — | хуже Chrome с сервис-воркером и очередью — отброшено |

## Сервер

**Контракт.** Event v1, добавления без новой версии:
- `kind: call`, `source: android_calls`, `author: me`;
- `payload.data.call = { direction, number, name, started_at, duration_s, sim }`: `direction` ∈ `in`, `out`,
  `missed`, `rejected`, `unknown` (обязательное); остальное необязательное; `duration_s` ≥ 0; `payload.text`
  отсутствует.
- Описание — обычное событие `kind: text`, `source: android_calls`,
  `payload.data.continuation = { target: <id звонка>, on: true }`.

**Адреса** (токен звонков в `Authorization: Bearer`):

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/calls/ping` | 204 — проверка токена и связи из настроек приложения |
| `POST` | `/api/calls` | `{ direction, number?, name?, started_at, duration_s?, sim? }` → событие `call`. id — UUID из sha256 строки `call|<number>|<started_at>`: повтор и повторная установка не создают дубль. Новый → 201, повтор → 200; ответ `{ id }` |
| `POST` | `/api/calls/:id/note` | `{ note_id, text }` → событие `text`-продолжение звонка; `note_id` — UUID с телефона (повтор → 200). Неизвестный звонок → 404, пустой текст → 400 |

- **Токен.** `STREAM_CALLS_TOKEN` (≥ 32 символа) в `/srv/stream/.env`; `install.sh` дописывает его, если нет.
  Открывает только `/api/calls*`; на остальных адресах — 401. Токен владельца на `/api/calls*` тоже работает
  (для проверок с компьютера). Без `STREAM_CALLS_TOKEN` сервер стартует, `/api/calls*` отвечают 503.
- Событие уходит в поток `/api/live` как любое другое.
- Файлы: `src/server/calls.ts` (разбор тела, id, запись), маршруты в `src/server/http.ts`, `kind` в
  `contracts/event.schema.json`, проверка `payload.data.call` в `src/contracts/call.ts`.

## Клиент Stream (PWA)

- `projection.js`: событие `call` — обычный вид ленты (метки, связи, правки «в архив» и «удалить» работают;
  «изменить» для звонка недоступно — нет текста).
- Пузырь звонка: значок направления; «Входящий · 4 мин», «Исходящий · 12 с», «Пропущенный», «Отклонённый»;
  имя или номер (номер — ссылкой `tel:`); время. Кнопка «Описать» → строка ввода в режиме продолжения этого
  звонка (`composer.proceed`). Описание из уведомления показывается под звонком одним пузырём, как любое
  продолжение.
- Звонок без описания — без отметки в этом пакете; фильтр «без описания» — П2.
- Новый модуль `web/callbubble.js` → в список `VERSIONED` (`src/server/static.ts`).

## Приложение «Stream · звонки» (`android/`)

**Сборка.** Kotlin, Gradle (Kotlin DSL), один модуль `app`. `minSdk 29` (Android 10), `targetSdk` — последний
установленный SDK. Зависимости: AndroidX Core, WorkManager (`work-runtime-ktx`); без Compose, без OkHttp —
экран на обычных View, сеть на `HttpURLConnection`, JSON — `org.json`. Пакет `pl.sekond.stream.calls`.

**Разрешения:** `READ_CALL_LOG`, `READ_PHONE_STATE`, `POST_NOTIFICATIONS`, `INTERNET`,
`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. `allowBackup=false` (токен не уезжает в облачную копию Android).

**Экран настроек** (единственный): адрес сервера (по умолчанию `https://stream.sekond.pl`), токен звонков,
«Проверить связь» (`/api/calls/ping`), кнопки выдачи разрешений с их состоянием, «Не экономить батарею»,
последняя отправка и число звонков в очереди.

**Как ловится звонок:**
1. Приёмник `PHONE_STATE` (в манифесте): переход в `IDLE` → разовая задача «сверить журнал» через 3 с (журнал
   вызовов дописывается чуть позже конца звонка).
2. Периодическая задача раз в 15 минут — та же сверка: досылает то, что пропустил приёмник (убитый фон,
   перезагрузка).
3. Сверка читает `CallLog.Calls` с `_ID` больше последнего отправленного; при первом запуске — только звонки
   после установки (старую историю не выгружаем). Каждую запись → `POST /api/calls`; успех → запоминается
   `_ID`. Без сети задача ждёт сеть (ограничение WorkManager) и повторяется с паузой.

Соответствие типов журнала: `INCOMING` → `in`, `OUTGOING` → `out`, `MISSED` → `missed`, `REJECTED` и
`BLOCKED` → `rejected`, остальное → `unknown`. Имя — `CACHED_NAME` журнала (без доступа к контактам).

**Уведомление после звонка:** только для разговоров (`in` / `out` с длительностью > 0), отправленных в течение
10 минут после конца звонка — досланные позже сверкой и пропущенные попадают в ленту молча.
Текст: «Входящий · 4 мин · Имя» и «О чём был звонок?»; действия «Описать» (поле ответа, голос — микрофоном
клавиатуры) и «Не нужно». Ответ сохраняется в очередь задачей WorkManager с `note_id`, уведомление сменяется на
«Записано»; отправка — `POST /api/calls/:id/note`, без сети — позже. Если звонок ещё не дошёл до сервера,
описание ждёт его.

## Подпись, установка, обновления

- Ключ подписи — `%USERPROFILE%\.stream\stream-calls.jks`, пароль — в `android/keystore.local.properties`
  (в `.gitignore`). Владельцу — сохранить ключ в надёжном месте: без него обновление не встанет поверх.
- Сборка — `gradlew assembleRelease` на этом компьютере; установка — по USB (`adb install -r`) после включения
  отладки по USB; запасной путь — файл APK себе на телефон.
- Токен звонков владелец вводит один раз (`sudo grep CALLS /srv/stream/.env`).
- Если Android не даёт выдать разрешение приложению не из магазина — «Сведения о приложении» → ⋮ →
  «Разрешить ограниченные настройки» (`CONCEPT.md` §8); в инструкции на экране настроек.

## Проверки

- **Сервер** (`node --test`): тело и типы, повтор без дубля (тот же id), токен звонков только на
  `/api/calls*`, токен владельца на `/api/calls*`, 503 без токена звонков, описание привязано к звонку,
  неизвестный звонок → 404, событие доходит до `/api/live`.
- **Приложение:** JVM-тесты на соответствие типов журнала, сборку тела запроса и выбор «уведомлять или нет».
  На эмуляторе (`Medium_Phone`, API 37): `adb emu gsm call <номер>` / `gsm accept` / `gsm cancel` →
  звонок в ленте локального сервера, уведомление, ответ из уведомления → описание под звонком; режим полёта →
  очередь → отправка после сети.
- **Владелец на телефоне:** входящий, исходящий, пропущенный; описание из шторки; телефон в кармане
  полчаса после звонка (фон не убит); перезагрузка.

## Готово, когда (проверяет владелец)

- [ ] Приложение установлено, разрешения выданы, «Проверить связь» — зелёная.
- [ ] После входящего, исходящего и пропущенного звонка он в ленте за несколько секунд.
- [ ] Описание из уведомления — под звонком; «Описать» в ленте тоже работает.
- [ ] Звонок без сети доходит после её появления, без дублей.
- [ ] Неделя использования; итог в `PLAN.md`: сколько звонков, сколько описано, чего не хватило.

## Решения исполнителя (можно поправить)

- Уведомление только после разговоров, не после пропущенных; окно 10 минут.
- Старую историю звонков при установке не выгружаем.
- Токен владельца тоже открывает `/api/calls*`.
- Имя — из журнала вызовов, без разрешения на контакты.
- Описание звонка, сделанное в Stream, правится как обычное сообщение; описание из уведомления — тоже.
