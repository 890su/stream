# П10 — Звонки и SMS в журнале: компаньон «Stream · телефон» на Kotlin

Концепция: `CONCEPT.md` §8.1. Решения: `decisions.md` 2026-11-17 «Звонки в журнале», «Компаньон звонков —
отдельное приложение на Kotlin», «SMS в журнале».

## Зачем

После звонка владелец за несколько секунд записывает, о чём был разговор и чем закончился; SMS с клиентами
ложатся в ту же ленту. Звонок, SMS и описание лежат рядом и попадают в тему дела; на шаге 3 их разбирает ИИ.
Сейчас договорённости по телефону и в SMS нигде не фиксируются.

- **Цель:** каждый звонок (входящий, исходящий, пропущенный, отклонённый) и каждое SMS с настоящего номера —
  в ленте; описание звонка — одним ответом из уведомления; ничего не теряется без сети и при убитом фоне.
- **Не цель:** запись разговора, расшифровка, чаты RCS и MMS, привязка номера к контакту справочника (П7),
  вечерняя сводка (шаг 6), чтение уведомлений других приложений, отправка SMS из Stream, Google Play.
- **Анти-цель:** приложение, которое нужно открывать или настраивать снова; уведомления, которые раздражают;
  коды подтверждения и банковские SMS в журнале; токен владельца на телефоне вне Stream.

## Подходы (выбрано 2026-11-17)

| Подход | Плюсы | Минусы |
|---|---|---|
| Tasker / MacroDroid | за вечер, без своего кода | направление и длительность ненадёжны; токен в чужом приложении — **отменено владельцем** |
| **Отдельное приложение на Kotlin** — выбрано | точные данные журнала, своя очередь, Stream не трогаем | два значка на телефоне |
| Stream в оболочке TWA + телефон | один значок | переустановка Stream, проверка «Поделиться» и ярлыков заново; позже, код переносится |
| Своя оболочка на WebView | — | хуже Chrome с сервис-воркером и очередью — отброшено |

## Сервер

**Контракт.** Event v1, добавления без новой версии; `source: android_phone`, `author: me`:
- `kind: call`, `payload.data.call = { direction, number, name, started_at, duration_s, sim }`: `direction` ∈
  `in`, `out`, `missed`, `rejected`, `unknown` (обязательное), остальное необязательное, `duration_s` ≥ 0;
  `payload.text` нет.
- `kind: sms`, `payload.text` — текст SMS, `payload.data.sms = { direction, number, name, sent_at, sim }`:
  `direction` ∈ `in`, `out`.
- Описание звонка — событие `kind: text`, `payload.data.continuation = { target: <id звонка>, on: true }`.

**Адреса** (токен телефона в `Authorization: Bearer`):

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/phone/ping` | 204 — проверка токена и связи из настроек приложения |
| `POST` | `/api/phone/calls` | `{ direction, number?, name?, started_at, duration_s?, sim? }` → событие `call`. id — UUID из sha256 строки `call|<number>|<started_at>`: повтор и повторная установка не создают дубль. Новый → 201, повтор → 200; ответ `{ id }` |
| `POST` | `/api/phone/calls/:id/note` | `{ note_id, text }` → событие `text`-продолжение звонка; `note_id` — UUID с телефона (повтор → 200). Неизвестный звонок → 404, пустой текст → 400 |
| `POST` | `/api/phone/sms` | `{ direction, number, name?, sent_at, text, sim? }` → событие `sms`. id — UUID из sha256 `sms|<direction>|<number>|<sent_at>|<text>`. 201 / 200, ответ `{ id }` |

- **Токен.** `STREAM_PHONE_TOKEN` (≥ 32 символа) в `/srv/stream/.env`; `install.sh` дописывает его, если нет.
  Открывает только `/api/phone/*`; на остальных адресах — 401. Токен владельца на `/api/phone/*` тоже работает
  (проверки с компьютера). Без `STREAM_PHONE_TOKEN` сервер стартует, `/api/phone/*` с токеном телефона → 401.
- Лимиты: текст SMS и описания — как у обычного события (`max_event_bytes`).
- События уходят в поток `/api/live` как любые другие.
- Файлы: `src/server/phone.ts` (разбор тела, id, запись), маршруты в `src/server/http.ts`, значения `kind` в
  `contracts/event.schema.json`, проверка `payload.data.call` / `payload.data.sms` в `src/contracts/phone.ts`.

## Клиент Stream (PWA)

- `projection.js`: события `call` и `sms` — обычный вид ленты (метки, связи, «в архив», «удалить» работают;
  «изменить» для них недоступно: у звонка нет текста, текст SMS чужой или уже отправлен).
- Пузырь звонка: значок направления; «Входящий · 4 мин», «Исходящий · 12 с», «Пропущенный», «Отклонённый»;
  имя или номер (номер — ссылкой `tel:`); время. Кнопка «Описать» → строка ввода в режиме продолжения этого
  звонка (`composer.proceed`). Описание из уведомления — под звонком одним пузырём, как любое продолжение.
- Пузырь SMS: «✉ Входящее SMS · имя» / «✉ Отправленное SMS · имя», текст (кат для длинного), время.
  Входящие SMS — у левого края, как чужие сообщения; отправленные и звонки — как свои.
- Новый модуль `web/phonebubble.js` → в список `VERSIONED` (`src/server/static.ts`).

## Приложение «Stream · телефон» (`android/`)

**Сборка.** Kotlin, Gradle (Kotlin DSL), один модуль `app`. `minSdk 29` (Android 10), `targetSdk` — последний
установленный SDK. Зависимости: AndroidX Core, WorkManager (`work-runtime-ktx`); без Compose, без OkHttp —
экран на обычных View, сеть на `HttpURLConnection`, JSON — `org.json`. Пакет `pl.sekond.stream.phone`.

**Разрешения:** `READ_CALL_LOG`, `READ_PHONE_STATE`, `READ_SMS`, `RECEIVE_SMS`, `POST_NOTIFICATIONS`,
`INTERNET`, `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. `allowBackup=false` (токен не уезжает в облачную копию).

**Экран настроек** (единственный): адрес сервера (по умолчанию `https://stream.sekond.pl`), токен телефона,
«Проверить связь» (`/api/phone/ping`), кнопки разрешений с состоянием, «Не экономить батарею», переключатели
«Звонки» и «SMS», исключения SMS (номера через запятую), последняя отправка и размер очереди; подсказка про
«Разрешить ограниченные настройки».

**Как ловится:**
1. Приёмник `PHONE_STATE` (манифест): переход в `IDLE` → разовая сверка через 3 с (журнал вызовов дописывается
   чуть позже конца звонка). Приёмник `SMS_RECEIVED` → разовая сверка через 2 с.
2. Периодическая сверка раз в 15 минут: досылает пропущенное и **отправленные SMS** (о них Android сообщает
   только SMS-приложению по умолчанию).
3. Сверка читает `CallLog.Calls` и `Telephony.Sms` (входящие и отправленные) с `_ID` больше последнего
   отправленного; при первом запуске — только после установки (старую историю не выгружаем). Каждую запись →
   свой адрес; успех → запоминается `_ID`. Без сети — ждёт сеть и повторяется с паузой. Звонки и SMS
   отправляются по порядку, одна сверка за раз (уникальная задача WorkManager).

Типы журнала вызовов: `INCOMING` → `in`, `OUTGOING` → `out`, `MISSED` → `missed`, `REJECTED` и `BLOCKED` →
`rejected`, остальное → `unknown`. Имя — `CACHED_NAME` журнала (без доступа к контактам); у SMS имени нет —
пустое (в ленте — номер).

**Фильтр SMS:** сохраняются только SMS с номеров (цифры, `+`, пробелы, скобки, дефисы); отправители с
буквами (банки, доставка, сервисы) и номера из исключений пропускаются, но `_ID` запоминается — к ним сверка
не возвращается. Короткие номера (до 6 цифр) — тоже служебные, пропускаются.

**Уведомление после разговора:** только `in` / `out` с длительностью > 0, отправленные в течение 10 минут после
конца звонка — досланные позже, пропущенные и SMS идут в ленту молча. Текст «Входящий · 4 мин · Имя» и «О чём
был звонок?»; действия «Описать» (поле ответа, голос — микрофоном клавиатуры) и «Не нужно». Ответ — в очередь
задачей WorkManager с `note_id`, уведомление сменяется на «Записано»; отправка после звонка (id звонка
считается на телефоне той же формулой, что на сервере, поэтому описание ждёт без связи).

## Подпись, установка, обновления

- Ключ подписи — `%USERPROFILE%\.stream\stream-phone.jks`, пароль — в `android/keystore.local.properties`
  (в `.gitignore`). Владельцу — сохранить ключ в надёжном месте: без него обновление не встанет поверх.
- Сборка — `gradlew assembleRelease` на этом компьютере; установка — по USB (`adb install -r`) после включения
  отладки по USB; запасной путь — файл APK себе на телефон.
- Токен телефона владелец вводит один раз (`sudo grep PHONE /srv/stream/.env`).
- Если Android не даёт выдать разрешение приложению не из магазина — «Сведения о приложении» → ⋮ →
  «Разрешить ограниченные настройки».

## Проверки

- **Сервер** (`node --test`): тела и типы, повтор без дубля (тот же id), токен телефона только на
  `/api/phone/*`, токен владельца на `/api/phone/*`, описание привязано к звонку, неизвестный звонок → 404,
  события доходят до `/api/live`, проверка контракта `call` / `sms` на `/api/events`.
- **Приложение:** JVM-тесты — типы журнала, фильтр SMS, тела запросов, id звонка (совпадает с серверным на
  общем примере), «уведомлять или нет». На эмуляторе (`Medium_Phone`, API 37): `adb emu gsm call` / `accept` /
  `cancel`, `adb emu sms send <номер> <текст>` → события в ленте локального сервера; уведомление, ответ →
  описание под звонком; режим полёта → очередь → отправка после сети; SMS с буквенного отправителя не приходит.
- **Владелец на телефоне:** входящий, исходящий, пропущенный; входящее и отправленное SMS; описание из шторки;
  полчаса в кармане после звонка (фон не убит); перезагрузка.

## Решения исполнителя (можно поправить)

- Уведомление только после разговоров, не после пропущенных и SMS; окно 10 минут.
- Старую историю звонков и SMS при установке не выгружаем.
- Токен владельца тоже открывает `/api/phone/*`.
- Имя — из журнала вызовов, без разрешения на контакты.
- SMS с буквенных и коротких номеров не сохраняются; свои исключения — в приложении.
- Звонок и SMS в Stream не правятся; описание звонка — правится как обычное сообщение.
